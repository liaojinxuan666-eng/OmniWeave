# OmniWeave (万象织构)

> **一个旨在打破“参数量霸权”的新型神经网络架构。**
> 
> 核心思想：**将“推理逻辑”与“死知识”解耦。**
> 用极少的参数（激活参数 0.2B）作为逻辑引擎，用海量外部记忆（潜意识库）存放知识，实现“小参数、全知全能”的智能体。

---

## 🧠 为什么我们需要 OmniWeave？

当前的大语言模型（如 GPT、Claude）陷入了“规模至上”的军备竞赛。但这造成了巨大的浪费：
1. **参数冗余**：模型 90% 的参数都在死记硬背静态事实（如：法国的首都是哪），只有极少数参数在真正进行逻辑推理。
2. **算力枷锁**：因为全量参数参与运算，推理成本极高，无法在端侧设备部署。
3. **元认知缺失**：模型不知道自己不知道，只会盲目输出。

**OmniWeave 的愿景是：**
让模型的总参数量可以很大（包含丰富的知识库），但每次推理时，**真正参与激活和计算的逻辑引擎只有 0.几B。** 
模型不需要把字典背在脑子里，它只需要学会“举一反三”，并在需要时，神不知鬼不觉地调用“潜意识记忆”。

## 🏛️ 核心架构总览

```text
     输入 (Input)
        │
        ▼
┌───────────────────────────────────────┐
│           MetaWeave (外置元认知)         │
│  - 不确定性估计 (Entropy/Confidence)    │
│  - 决策循环：重试 / 工具 / 慢思考         │
│  - 反思记忆 (Reflection Memory)         │
└──────────────────┬────────────────────┘
                   │
                   ▼
┌───────────────────────────────────────┐
│         OmniWeave (主干网络)            │
│                                       │
│  ┌──────────────┐    ┌─────────────┐  │
│  │   Router     │───▶│  Operators   │  │
│  │ (硬件感知)    │    │  (SSM/KAN等) │  │
│  └──────────────┘    └─────────────┘  │
│         │                  │          │
│         ▼                  ▼          │
│  ┌─────────────────────────────────┐  │
│  │      MemWeave (潜意识记忆)       │  │
│  │  - DynamicMemorySlots (动态槽)   │  │
│  │  - 快/温/冷 三级记忆结构          │  │
│  └─────────────────────────────────┘  │
└───────────────────────────────────────┘
 
1. 动态记忆槽 (MemWeave)
 
抛弃了传统 Transformer 的 KV Cache，采用 DynamicMemorySlots。
• 记忆不再是静态存储，而是由“写入门控”和“遗忘门控”动态更新的神经网络参数矩阵。
• 模型在推理时，知识像“潜意识”一样被无缝激活，无需刻意去“翻数据库”（RAG）。
• 记忆更新与梯度计算隔离，极大降低显存占用。 
2. 动态路由与算子池 (OmniWeave)
 
打破“每层都是 Transformer”的死板结构。
• 算子池包含：SSM (Mamba)、线性注意力 (Linear Attention)、KAN、局部卷积。
• BudgetAwareRouter：根据当前硬件预算（延迟、内存）、输入不确定性，动态决定当前 Token 应该走哪个算子（Top-K 路由）。
• 负载均衡损失：防止路由坍缩，确保所有算子都能被有效训练。 
3. 外置元认知 (MetaWeave)
 
小参数模型永远无法在自身参数内实现通用元认知。
• 将元认知剥离到架构外部，由 MetaWeave 控制器 承担。
• 基于信息熵的不确定性估计，决定是否触发“慢思考”（调用外部工具、重新检索、或回退重试）。
• 元认知不参与主干模型参数更新，使 0.几B 的模型也能拥有“知道自己不知道”的能力。
